Understanding

「デザインシステムの導入・強化」
この一行の裏にある、
継続的な現場の負荷を理解しています。

01
Figmaと実装コードの間には、常に"翻訳"が必要です

デザイナーが定義するtoken・コンポーネントを、そのままOSに渡すことはできません。パラメータ設計とフォーマット決めという地味だが不可欠な工程を、有識者として引き受けます。

02
iOSとAndroid、2つの文法を同時に扱う必要があります

同じデザイントークンでも、iOSのpt/AutoLayoutとAndroidのdp/Composeでは設計思想が異なります。両OSの作法を理解した上でUI部品として提供することが求められる仕事だと理解しています。

03
属人化を避け、長期で安定運用できる体制が必要です

月160H・フルリモート・長期就業を前提とした募集内容から、単発の実装ではなく「開発チームに提供し続ける仕組み」自体の構築が本質的な課題だと捉えています。

What Kairos Provides

Kairosが提供できる価値

デザインシステムを「作って終わり」にせず、開発チームが日々使い続けられる形にするための実装力です。

01 / TOKEN

トークン・パラメータ設計

Figma上のtoken / コンポーネント定義を、デザイナーと連携しながら実装可能なパラメータへ変換。命名規則から粒度まで一貫した設計を行います。

02 / iOS

iOS向けUI部品実装

Human Interface Guidelinesを踏まえつつ、デザインシステムに準拠したコンポーネントとして再利用可能な形で提供します。

03 / Android

Android向けUI部品実装

Material Designの制約とプロダクト固有のデザインを両立させ、iOS版と一貫した見た目・挙動になるよう調整して実装します。

04 / RESOURCE

リソース・フォーマット標準化

画像などのリソースの命名・書き出しフォーマットを整備し、開発チームが迷わず取り込める配布フローを構築します。

05 / TEAM

長期伴走・ドキュメント化

属人化を避けるため、設計判断の背景をドキュメントに残しながら進行。月次160H体制での安定的な稼働を前提に対応します。

06 / SYNC

デザイナーとの協業フロー構築

顔出しMTGでの密な連携を前提に、デザイナー側の負荷を増やさず双方が確認しやすいレビュー・フィードバックの型を作ります。

Process

進め方・スケジュールイメージ

まずは小さく検証しながら、月160Hの安定稼働へと移行していきます。

PHASE 0 ・ Week 1

キックオフ・ヒアリング

PHASE 2 ・ Week 4-6

UI部品の実装・提供

iOS / Androidそれぞれのコンポーネントを実装し、開発チームへ順次提供します。

PHASE 3 ・ Month 2〜

継続運用・拡張体制へ

月160Hの安定稼働として、新規コンポーネントの追加やリファクタリングに継続対応します。
